## 2. Актуальный бэклог задач (Backlog)

### [x] Задача 1: Полиморфный Quiz Engine (Стратегии SINGLE_CHOICE, MULTIPLE_CHOICE, SHORT_ANSWER, CODE, FLASHCARD)
- **Цель**: Устранить хардкод типов вопросов, перевести движок квизов на гибкий полиморфный паттерн Strategy / Registry.
- **Требования архитектуры**:
  - Никаких разрозненных `if (type === ...)` в сервисах оценки и UI-компонентах.
  - Единый реестр стратегий `QuestionStrategyRegistry`.
  - Контракт стратегии должен включать:
    1. Zod-схему конфигурации вопроса и ответа студента.
    2. Серверный чистый Evaluator (Zero-Trust: проверка без утечки ответов на клиент).
    3. Клиентский Input-компонент в фабрике рендеринга `QuizStepper`.
    4. Редактор вопроса в шторке Студии (`/studio/[slug]`).
- **Критерии приемки (DoD)**:
  - [x] Реализованы и зарегистрированы стратегии:
    - `SINGLE_CHOICE`
    - `MULTIPLE_CHOICE`
    - `SHORT_ANSWER` (точный ввод / нормализация регистра и пробелов)
    - `CODE` (контракт кода и тест-кейсов)
    - `FLASHCARD` (самооценка / рендеринг карточки)
  - [x] Серверный `evaluateQuizSubmission` использует полиморфные Evaluator'ы.
  - [x] DTO для клиента не содержит правильных ответов (`correctAnswerIndexes`, эталонных строк, скрытых тестов).
  - [x] Написаны исчерпывающие юнит-тесты на каждую стратегию и реестр.
  - [x] `pnpm validate` проходит без регрессий (246 тестов зеленые).

### [ ] Задача 2: Песочница кода (Web Worker Runner) в рамках стратегии CODE
- **Цель**: Реализовать безопасное изолированное выполнение кода на клиенте и валидацию тестов на сервере.
- **Требования архитектуры**:
  - Клиентское выполнение в Web Worker (не блокирует UI-поток, изоляция от DOM и cookies).
  - Таймаут исполнения (защита от бесконечных циклов `while(true)`).
  - Безопасный перехват `console.log` и возвращаемого значения.
  - Серверная валидация: скрытые тесты запускаются изолированно при итоговой оценке.
- **Критерии приемки (DoD)**:
  - [ ] Web Worker Runner запускает пользовательский код с ограничением по времени (например, 2000 мс).
  - [ ] Перехватываются синтаксические ошибки, runtime exceptions и таймауты.
  - [ ] Клиентский компонент отображает редактор кода с подсветкой синтаксиса и панель вывода тестов.
  - [ ] Написаны модульные тесты для Runner'а и граничных случаев (таймаут, синтаксическая ошибка, корректный вывод).
  - [ ] `pnpm validate` успешен.

### [ ] Задача 3: Production Seed скрипт с демонстрацией всех типов вопросов и тиров
- **Цель**: Создать богатый демонстрационный курс в `prisma/seed.ts`, наглядно валидирующий все возможности платформы.
- **Требования архитектуры**:
  - Создание реалистичного курса (например, «Продвинутая архитектура распределенных систем»).
  - Разделение на 3 тира:
    1. *Tier 1: Фундаментальные основы* (CAP-теорема, ACID vs BASE).
    2. *Tier 2: Сетевые протоколы и консенсус* (Raft, Paxos, gRPC).
    3. *Tier 3: Отказоустойчивость и масштабирование* (Event Sourcing, CQRS).
  - Включение каждого типа вопроса:
    - `SINGLE_CHOICE`
    - `MULTIPLE_CHOICE`
    - `SHORT_ANSWER`
    - `CODE` (с тестами)
    - `FLASHCARD` (карточки для SM-2)
  - Граф связей: строгие пререквизиты (`REQUIRED`) и рекомендованные (`RECOMMENDED`), подтверждающие ацикличность (DAG).
- **Критерии приемки (DoD)**:
  - [ ] `pnpm db:seed` выполняется чисто и детерминированно.
  - [ ] Созданный курс корректно отображается в каталоге, Студии и Роадмапе.
  - [ ] `pnpm validate` проходит успешно.

## 3. Workflow выполнения задач (Definition of Done)

1. **Инициализация**:
   - Прочитать `docs/ARCHITECTURE_RULES.md`.
   - Выбрать задачу из бэклога, проверить зависимости.
2. **Разработка**:
   - Строго следовать Result Pattern (`createSafeAction`), Zod-валидации, Zero-Trust и Strategy/Registry.
   - Не трогать и не нарушать существующие 185+ тестов.
3. **Тестирование**:
   - Написать модульные тесты на новый функционал (позитивные и негативные сценарии).
4. **Валидация**:
   - Запустить `pnpm validate`.
   - Убедиться, что `typecheck`, все тесты и `next build` завершились с кодом 0.
5. **Фиксация**:
   - Отметить выполненные чекбоксы в `docs/TASK_QUEUE.md`.
